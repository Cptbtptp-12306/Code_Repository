# P2859 Stall Reservations S 详细思路
本题是经典的区间最少着色问题，题目等价于给定若干闭区间，要求给区间分配编号，相交的区间编号不能相同，求出最少需要多少编号，并且按照输入顺序输出每个区间对应的编号。

首先明确题目的约束条件，奶牛的挤奶时间段是闭区间A到B，一头奶牛在时刻B结束挤奶，另一头奶牛不能在时刻B开始挤奶，也就是只有当某个牛棚中上一头奶牛的结束时间严格小于当前奶牛的开始时间，这个牛棚才可以被复用。如果结束时间等于当前奶牛的开始时间，两个时间段仍然重叠，不能共用同一个牛棚。

整体贪心策略，我们优先处理开始时间更早的奶牛。先把所有奶牛按照挤奶开始时间从小到大排序，这样我们从头到尾依次安排奶牛，保证先安排早开始的奶牛，这是贪心能够得到最优解的基础。如果不按照开始时间排序，后面的安排逻辑会出错，无法保证求出最少牛棚。

排序之后，我们需要一个有序容器来维护所有正在被使用的牛棚信息，这里选用multimap。multimap的键保存牛棚里上一头奶牛的结束时间，值保存牛棚的编号。multimap底层是红黑树，内部会自动按照键从小到大排序，并且允许键重复，也就是多个牛棚可以在同一个时间点结束，这是普通map做不到的。

接下来遍历排序后的每一头奶牛，逐个进行牛棚分配。对于当前奶牛，取出它的开始时间和结束时间。我们调用multimap的lower_bound函数，传入当前奶牛的开始时间，这个函数会返回容器中第一个大于等于当前奶牛开始时间的元素对应的迭代器。这个迭代器相当于分界线，迭代器本身以及它右边所有的牛棚，结束时间都大于等于当前奶牛的开始时间，这些牛棚还在占用，不能复用。迭代器左边所有的牛棚，结束时间都严格小于当前奶牛的开始时间，这些牛棚已经空闲，可以拿来复用。

然后判断这个迭代器是否等于容器的开头。如果迭代器不等于容器开头，就说明分界线左边存在空闲的牛棚。因为容器是升序排列，分界线左边区间最靠右的元素，就是空闲牛棚里面结束时间最大的那一个。我们把迭代器向前移动一位，拿到这个牛棚，读取它的编号。之后我们需要删除这个牛棚旧的记录，因为这个牛棚要安排新的奶牛，旧的结束时间已经失效。再插入一条新的记录，牛棚编号保持不变，结束时间更新为当前奶牛的结束时间，最后把这个牛棚编号分配给当前奶牛。

如果迭代器等于容器开头，说明分界线左边没有任何空闲牛棚，现有的所有牛棚都和当前奶牛的时间段冲突，没有办法复用。这时我们需要新建一个牛棚，牛棚总数加一，把新牛棚的结束时间和编号存入multimap，并且把这个新的编号分配给当前奶牛。

在所有奶牛分配完成之后，我们得到了每一头排序之后奶牛的牛棚编号。但是排序打乱了奶牛原本的输入顺序，而题目要求按照原始输入顺序输出答案。所以在结构体里面我们提前保存了每一头奶牛原始的输入位置pos。我们开辟一个答案数组res，res数组的下标代表原始输入的奶牛序号，数组里面的值就是该奶牛对应的牛棚编号。我们遍历排序后的奶牛数组，执行res[a[i].pos]等于a[i].num，也就是把分配好的棚号放到原始序号对应的位置上，完成顺序还原。最后依次遍历res数组，按顺序输出里面的值，就是题目要求的输出结果。

算法的正确性原理，最少需要的牛棚数量，等于同一时间点重叠的区间的最大数量。这个贪心策略保证每次新增牛棚的时候，恰好是区间重叠到达峰值的时候。整个算法的时间复杂度主要由排序和multimap的操作决定，排序是nlogn，每一次查找、删除、插入都是logn级别，整体复杂度为nlogn，可以通过题目50000的数据范围。

额外说明容易出错的点，第一是闭区间的判断条件，不能使用upper_bound，upper_bound会把结束时间等于当前开始时间的牛棚判定为可用，造成时间冲突；第二是multimap删除的时候只能删除迭代器指向的单个元素，如果直接删除数值会删掉所有相同结束时间的牛棚；第三是不能忘记保存原始位置pos，否则答案输出顺序错乱。
